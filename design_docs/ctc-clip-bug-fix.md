# Task: Refactor `align_runner.py` to Enable CTC Forced Alignment (`--ctc`) in `@storyteller-platform/align`

## Background & Root Cause Analysis
We are experiencing a critical audio synchronization defect in the EPUB 3 Media Overlay (`.smil`) files generated by our current `@storyteller-platform/align` (`stalign` v0.2.4) wrapper in `align_runner.py`:
1. **Mid-Phoneme Clipping:** In our output SMIL files (e.g., `9781400229239_Chapter2.smil`), `clipBegin` and `clipEnd` markers are landing directly inside spoken words rather than in the acoustic silence between phrases. For example:
   - `<par id="Chapter2-s0">` has `clipBegin="422.460s" clipEnd="423.800s"` — `422.460s` starts right on the word "two" of "Chapter Two", and `423.800s` slices the word "A" in half at the start of "A Cheesy Love Song".
   - Every subsequent `<par>` element abuts the previous timestamp (`423.800s` -> `428.580s` -> `435.440s`), compounding the clipping across almost every clip indicator.
2. **Spec Non-Compliance & Playback Glitches:** These mid-word timestamps cause audible hiccups/pops in DTB playback systems and violate **NLS Specification 1203** (which governs clip time offsets and requires phrase boundaries to sit cleanly within inter-phrase silence/pauses so converted ANSI/NISO Z39.86-2002 DTBs pass validation).
3. **Why This Happens:** Without the `--ctc` flag, `stalign` defaults to its legacy `transcribe` + `error-align` pipeline using `whisper.cpp`. Whisper estimates word-level timestamps via cross-attention weights (DTW), which regularly drift by 50–200ms and land mid-phoneme.
4. **The Fix:** `@storyteller-platform/align@0.2.4` supports a CTC-based forced alignment algorithm (`--ctc`) that replaces `transcribe` with `emit` (analyzing 20ms acoustic frames via `mms` or `quartznet15x5` models). We need to update `align_runner.py` to use the `--ctc` pipeline and expose its relevant CLI parameters.
